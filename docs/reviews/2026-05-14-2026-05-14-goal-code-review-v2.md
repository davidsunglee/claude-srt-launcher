#### Minor (Nice to Have)

- **tests/profiles/inspect.test.ts: Deletion of the tmpdir-workspace coverage test removes documentation of a known design tension**
  - **What:** The removed test `'does NOT permit workspace-root writes when workspace lives under os.tmpdir()'` was testing the wrong expectation (it asserted `/tmp` absent from `allowWrite`, contrary to spec), but its inline comment explicitly documented the SRT sandbox's path-coverage rule (`wsUnderTmp.startsWith(entry + '/')`) and the design tension it implies: when the inspect workspace is located under `/tmp` or `$TMPDIR` (as the smoke test's `WS=$(mktemp -d ...)` produces), the workspace root becomes implicitly writable through the `/tmp` allowWrite entry. This is spec-correct behavior but still a meaningful operational caveat for users of the inspect profile.
  - **Why it matters:** The smoke test creates its workspace under `mktemp -d`, which on Linux lands under `/tmp` and on macOS lands under `$TMPDIR`. In both cases the smoke test's "inspect workspace-root write blocked" expectation may not hold in a real SRT run. Users should understand that inspect's workspace-root protection requires the workspace to live outside the system temp directory.
  - **Recommendation:** Add a short comment in `src/profiles/inspect.ts` near the `/tmp` and `$TMPDIR` entries explaining that the workspace should not be located under the system temp directory if workspace-root write isolation is required, and consider a corresponding note in `docs/profiles/inspect.md` under "Known holes".

- **tests/commands/run.test.ts:8: FAKE_HOME tmpdir is never cleaned up after the test file completes**
  - **What:** `FAKE_HOME` is created with `fs.mkdtempSync` at module load time; `beforeEach` cleans its contents but the directory itself is never removed (no `afterAll(() => fs.rmSync(FAKE_HOME, { recursive: true }))`).
  - **Why it matters:** Each vitest run leaks one temp directory; accumulates in CI over time.
  - **Recommendation:** Add `afterAll(() => fs.rmSync(FAKE_HOME, { recursive: true, force: true }))` to clean up after the test suite.

### Recommendations

- Consider adding a note to `docs/profiles/inspect.md` warning users that the `/tmp` and `$TMPDIR` allowances mean workspaces created under the system temp directory (e.g., via `mktemp`) will have implicit root-level write access in inspect mode, and that production use of inspect for mutation-sensitive review should use a workspace outside those directories.
