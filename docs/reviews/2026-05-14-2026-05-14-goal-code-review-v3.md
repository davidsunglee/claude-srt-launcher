### Issues

#### Important (Should Fix)

- **`scripts/smoke-test.sh:38` and `scripts/smoke-test.sh:217-222`: Inspect smoke check uses a temp workspace that is covered by the inspect profile's temp write allow-list**
  - **What:** The smoke script creates `WS` with `mktemp -d` (`scripts/smoke-test.sh:38`) and later expects `claude-srt exec --profile inspect ... 'echo nope > "$WS/blocked.txt"'` to fail (`scripts/smoke-test.sh:217-222`). However, the inspect policy explicitly allows writes to `/tmp` and `$TMPDIR` (`src/profiles/inspect.ts:23-24`). On macOS and typical Unix shells, `mktemp -d -t ...` creates the workspace under the same temp root that Node substitutes for `$TMPDIR`/`os.tmpdir()`, so the workspace root is implicitly writable through the temp-directory allowance.
  - **Why it matters:** The project requirement is to ship an executable smoke test that verifies allow/deny behavior end-to-end. This check is intended to prove inspect mode blocks workspace-root writes, but under the real recursive path semantics needed by the rest of the policy it can instead succeed and make `npm run smoke` fail even when SRT is enforcing the rendered policy correctly. The README repeats the same claim that inspect root writes are denied (`README.md:75-76`), which is not true for workspaces placed under `$TMPDIR`.
  - **Recommendation:** Move the smoke-test workspace used for inspect mode outside `/tmp`/`$TMPDIR` (for example, create a temporary directory under the repository or another non-temp parent and clean it up), or add an explicit policy design that can deny the workspace root while still allowing temp writes. Also document the operational caveat in `docs/profiles/inspect.md` because its current statement that “All other writes inside `<workspace>` are denied” (`docs/profiles/inspect.md:30`) is only true when the workspace is not nested under another allowed write path.

#### Minor (Nice to Have)

- **`tests/commands/run.test.ts:10-15`: Temporary directories created at module load are not removed**
  - **What:** `FAKE_HOME` and `FAKE_TMPDIR` are created with `fs.mkdtempSync`, but the test file only clears contents between tests and does not remove the directories after the suite.
  - **Why it matters:** Each test run leaks two directories in the system temp area, which is small but avoidable CI/developer-machine clutter.
  - **Recommendation:** Import `afterAll` from Vitest and remove both directories with `fs.rmSync(..., { recursive: true, force: true })`.

### Recommendations

- Add an integration/smoke dry-run mode or a documented preflight that prints the rendered inspect `allowWrite` paths alongside the smoke workspace path; this would make path-containment mistakes easier to catch without requiring a full SRT run.
