### Outcome

**Verdict:** Not approved

**Reasoning:** The implementation covers most of the planned CLI, profile, test, and documentation surface, and the TypeScript build plus unit tests pass. However, the inspect profile has a policy hole that permits workspace-root writes when the workspace is under an allowed temp directory, contradicting a core safety guarantee and causing the shipped smoke test's inspect deny check to be invalid/failing.

### Strengths

- The rendered policy type mirrors the required SRT settings keys exactly, which reduces the chance of silently emitting unusable settings JSON (`src/profiles/types.ts:1-18`).
- The shared base policy consistently disables local binding and all Unix sockets while denying host Claude and SSH state in both read and write lists (`src/profiles/base.ts:25-50`).
- Build egress selection is centralized through `composeProfileFor`, so `--unsafe=build-with-egress` flows through the command layer from one place (`src/commands/compose.ts:17-22`).
- Verification evidence: `npm run build` succeeded, and `npm test` passed all 12 test files / 88 tests in this checkout.

### Issues

#### Critical (Must Fix)

- **src/profiles/inspect.ts:17: Inspect write policy is bypassed for temp-based workspaces**
  - **What:** The inspect profile allows writes to `/tmp` and `$TMPDIR` while relying on the absence of `<workspace>` from `allowWrite` to block workspace-root writes. If the workspace lives under either temp directory, the broader temp allow-list grants write access to the entire workspace anyway. The shipped smoke test creates `WS` with `mktemp` (`scripts/smoke-test.sh:38`) and then expects `echo nope > "$WS/blocked.txt"` to be denied (`scripts/smoke-test.sh:217-221`), so it exercises this exact bypass.
  - **Why it matters:** The inspect profile's central safety promise is read-mostly review/verification with no source-tree mutation. For temp workspaces, that guarantee is false, and the end-to-end smoke test will either fail or fail to prove the intended restriction.
  - **Recommendation:** Ensure workspace paths cannot be descendants of broad writable temp paths for inspect runs, or replace global `/tmp`/`$TMPDIR` write grants with a per-invocation temp directory that cannot contain the workspace. Add a regression test/render check for an inspect workspace under `os.tmpdir()`.

#### Important (Should Fix)

- **src/state/claude-home.ts:23: `host-claude-home` does not actually point Claude at the host Claude home**
  - **What:** `applyUnsafeOverrides` removes `~/.claude` from the deny lists (`src/overrides/unsafe.ts:52-58`), but command execution still derives `claudeState` via `claudeConfigDirFor(stateDir)`, which always appends `/.claude` (`src/state/claude-home.ts:23-24`, `src/commands/run.ts:28-33`). Passing `--state-dir ~/.claude --unsafe=host-claude-home` renders/uses `~/.claude/.claude`, while using the override without `--state-dir` exposes host `~/.claude` but keeps Claude on the isolated state.
  - **Why it matters:** The override is documented/planned as sharing the host Claude state, but the implementation either fails to share it or grants unnecessary host-state access to arbitrary commands. That is a functional bug in an explicit unsafe gate.
  - **Recommendation:** When `host-claude-home` is granted, set `CLAUDE_CONFIG_DIR` and the `<claude-state>` substitution to `path.join(os.homedir(), '.claude')` directly, or clearly require/support `--state-dir $HOME` with tests and documentation that reflect that behavior.

- **package.json:12: `npm run smoke` can run stale or missing build artifacts**
  - **What:** The `smoke` package script invokes `bash scripts/smoke-test.sh`, but the script itself does not build before calling `node dist/cli.js`. Only the `just smoke` recipe performs `build-ts` first.
  - **Why it matters:** The plan requires the smoke test to exercise the current code path end-to-end. Running stale `dist/` output can hide regressions, and a fresh checkout without `dist/` will fail before testing the sandbox behavior.
  - **Recommendation:** Make either `package.json` use `"smoke": "npm run build && bash scripts/smoke-test.sh"` or add an explicit build step at the beginning of `scripts/smoke-test.sh`.

#### Minor (Nice to Have)

- **src/cli.ts:53: Value-taking flags do not reject missing values**
  - **What:** Flags such as `--workspace`, `--state-dir`, and `--unsafe` consume `argv[++i]` without verifying that a value exists or that the next token is not another flag.
  - **Why it matters:** A typo like `--workspace` at the end silently falls back to the current working directory, which is surprising for a safety-sensitive launcher.
  - **Recommendation:** Add a small helper for required flag values and throw a usage error when the value is missing or starts with `--`.

### Recommendations

- Add integration-style tests that render and reason about path ancestry, not just exact array membership, for profiles whose safety properties depend on one path not being writable through another allow-list entry.
