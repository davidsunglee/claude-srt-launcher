## Goal

Build a standalone TypeScript/Node CLI (`claude-srt`) plus `justfile` recipes that launch Claude Code under Anthropic Sandbox Runtime (`@anthropic-ai/sandbox-runtime`) using four named, code-validated policy profiles (`interactive`, `build`, `inspect`, `ios`). The launcher composes per-profile SRT settings JSON, enforces an isolated Claude state directory by default, performs disposable-workspace and unsafe-override gating, and ships an executable smoke test plus README documentation describing the safety stance and remaining holes.

## Architecture summary

The launcher is a single-process Node CLI that owns the trust boundary. Profile definitions live as TypeScript modules that produce typed `PolicyFragment` values; a composition layer merges a shared base policy with the chosen profile, applies gated unsafe overrides, substitutes runtime tokens (`<workspace>`, `<claude-state>`), validates the result, and renders an SRT-shaped settings JSON to a per-invocation tempfile. A runner spawns the `srt` binary with `--settings <tempfile>` plus the user-requested inner command (`claude` by default, an arbitrary command for `exec`, an interactive bootstrap session for `bootstrap`). Isolated Claude state lives under `~/.claude-srt-launcher/state/<profile>/.claude` and is selected via `CLAUDE_CONFIG_DIR`. The `justfile` is a thin convenience wrapper over the CLI; the `scripts/smoke-test.sh` smoke test exercises allow/deny behavior end-to-end through the same code path. Unit tests (vitest) lock down the rendered policy shape per profile.

## Tech stack

- Node.js 20+ (built-in fetch, ESM)
- TypeScript 5.x compiled with `tsc` to `dist/`
- `@anthropic-ai/sandbox-runtime` (peer dep — provides the `srt` CLI on PATH; we shell out, not link in)
- `vitest` for unit tests
- `just` for ergonomic recipes
- POSIX `bash` + `curl` + `jq` for the smoke-test script
- No third-party CLI parser, no logger, no schema library — keep dependency surface minimal for a security-sensitive tool

- `src/commands/render.ts` (Create) — `claude-srt render --profile <name>` — prints the composed SRT settings JSON to stdout (no execution); useful for tests, audits, and the `--dry-run` flow on `run`.

- `src/profiles/base.ts` (Create) — Shared base `PolicyFragment` consumed by every profile: Claude service domains, broad credential/keychain/browser-data deny-reads, `allowLocalBinding: false`, `allowAllUnixSockets: false`, `enableWeakerNestedSandbox: false`, `enableWeakerNetworkIsolation: false`.
- `src/profiles/interactive.ts` (Create) — Adds GitHub + package-manager domains, workspace read/write, common dev-cache read/write, isolated `<claude-state>` read/write.
- `src/profiles/build.ts` (Create) — Adds disposable-workspace read/write, isolated `<claude-state>` read/write; deliberately does NOT add GitHub/package-manager domains; exposes a `withEgress` variant gated by named override.
- `src/profiles/inspect.ts` (Create) — Workspace read-only; writes restricted to `/tmp`, `$TMPDIR`, `<workspace>/test-output`, `<workspace>/reports`, `<workspace>/.cache`, `~/.cache`, `<claude-state>`; minimal review-only network (api.github.com, raw.githubusercontent.com, codeload.github.com).
- `src/profiles/ios.ts` (Create) — Extends interactive; adds Apple developer/Simulator domains, Xcode and CoreSimulator caches/derived-data read/write, mach-lookup entries for simulator services; explicitly continues to deny `~/Library/Keychains` and `~/Library/MobileDevice/Provisioning Profiles`.
- `src/profiles/index.ts` (Create) — `getProfile(name: ProfileName): PolicyFragment` registry, plus `listProfiles()`.
- `src/policy/compose.ts` (Create) — Pure merge: arrays union (deduped), object scalars right-wins; takes `[base, profile, overrides]` and produces a single `PolicyFragment`.
- `src/policy/substitute.ts` (Create) — Replaces `<workspace>`, `<claude-state>`, `$TMPDIR`, `~` tokens against runtime `Substitutions`; absolutizes paths.
- `src/policy/validate.ts` (Create) — Asserts invariants on a substituted `PolicyFragment`: `allowLocalBinding === false` unless explicit unsafe override carries it; `allowAllUnixSockets === false` unless explicit unsafe override carries it; `denyRead`/`denyWrite` always include the host `~/.claude` and `~/.ssh` (unless an unsafe override removes them); no overlap between final `allowWrite` and `denyWrite` for credential paths. Throws `PolicyValidationError` with a list of violations.
- `src/policy/render.ts` (Create) — Converts a validated `PolicyFragment` to the exact SRT settings JSON shape (`{ network: {...}, filesystem: {...}, enableWeakerNestedSandbox, enableWeakerNetworkIsolation }`); writes to a tempfile via `fs.mkdtemp` and returns the path.
- `src/state/claude-home.ts` (Create) — `resolveClaudeStateDir(profile)` returns `~/.claude-srt-launcher/state/<profile>`; `ensureClaudeStateDir(path)` creates it (mode `0700`) and the `.claude/` subdir if missing; `claudeConfigDirFor(stateDir)` returns the path to assign to `CLAUDE_CONFIG_DIR`.
- `src/state/workspace.ts` (Create) — `assertDisposableWorkspace(path, opts)` checks for a `.srt-disposable` marker file in `path`, OR `opts.disposableFlag === true`, OR `opts.unsafeNonDisposable === true`; throws `WorkspaceNotDisposableError` otherwise. `resolveWorkspace(cwd, override?)` normalizes to absolute path and rejects if it does not exist.
- `src/commands/compose.ts` (Create) — `composeProfileFor(parsed)`: single composition entry point shared by `render`, `run`, `exec`, and `bootstrap`. Calls `getProfile('build', { withEgress: parsed.unsafeOverrides.has('build-with-egress') })` for the build profile and `getProfile(parsed.profile)` otherwise, then applies `applyUnsafeOverrides`.
- `src/overrides/unsafe.ts` (Create) — Parses `--unsafe=<name>[,<name>...]` into a typed `Set<UnsafeOverride>`. Recognized names (each a discrete, named gate, not a free-form flag): `host-claude-home`, `local-binding`, `all-unix-sockets`, `non-disposable-workspace`, `build-with-egress`, `ios-codesigning`. Unknown names hard-fail with the full allowed list in the error message.
- `src/runner/srt.ts` (Create) — `runSrt({ settingsPath, command, env })`: locates `srt` on PATH (errors with the install command if missing), spawns `srt --settings <path> <cmd...>` with inherited stdio and the merged env, returns the exit code. Cleans up the tempfile in a `finally` block on signals (SIGINT/SIGTERM) and process exit.
- `src/runner/claude-args.ts` (Create) — Builds the inner `claude` argv: passes through any `--`-separated user args, applies `--dangerously-skip-permissions` only when invoking `build` AND the disposable-workspace check passed AND the user supplied `--unattended`.
- `src/util/paths.ts` (Create) — `expandTilde`, `expandTmpdir`, `isInside(parent, child)` helpers for substitution and validation.
- `scripts/smoke-test.sh` (Create) — Bash script that builds the project, then exercises `claude-srt exec --profile interactive --` against allow and deny cases (workspace write OK, `~/.ssh/known_hosts` read denied, `https://api.github.com` reachable when allowed, `https://malicious.invalid` denied, etc.), emitting `PASS`/`FAIL` per check and exiting non-zero on any fail.

## Risk Assessment

- **Claude service domain list is empirically derived.** The base profile lists `api.anthropic.com`, `statsig.anthropic.com`, `console.anthropic.com`, `claude.ai`, `*.claude.ai`, `sentry.io`, `*.sentry.io`. If Claude Code talks to additional first-party domains in some flows (auth callbacks, model discovery), it will fail under the wrapper until the list is updated. Mitigation: the smoke test runs `claude --version` (when claude is installed) and the bootstrap mode is the first place a real interactive session will surface unknown domains; document in the README that adding to base.ts requires re-running `npm test` to confirm no profile regressions.
- **`HOME`/`CLAUDE_CONFIG_DIR` interaction.** We rely on `CLAUDE_CONFIG_DIR` (confirmed in the official Claude Code devcontainer config) rather than overriding `HOME`. If a future Claude Code release ignores the env var on a code path, the wrapper could silently fall back to host `~/.claude`. Mitigation: the base policy denies host `~/.claude` reads and writes — a regression would surface as a sandbox violation, not silent leakage. The bootstrap mode test should explicitly confirm new files appear under the isolated state dir, not under `~/.claude`.
- **macOS `allowLocalBinding` weakness.** The spec calls this out explicitly. The launcher refuses to enable it without the named `--unsafe=local-binding` override. The README and per-profile docs warn that enabling it on macOS may weaken outbound restrictions. No code-level workaround is in scope for this release.
- **Disposable-workspace marker is filesystem-based and not tamper-proof.** A user (or a malicious tool inside Claude Code) could write `.srt-disposable` into any directory. This is a workflow guardrail, not a security control; the per-profile doc states this explicitly.
- **iOS profile breadth.** Xcode and Simulator workflows can touch a wide variety of paths (custom DerivedData locations, custom toolchains, third-party simulator runtimes). The default allow-list covers the common case; users with unusual setups will need to extend the profile or pass per-invocation paths. We do NOT add a "wide-open Xcode" override in this release.
- **Smoke-test environmental sensitivity.** The smoke test uses `https://malicious.invalid.example` as a deny target, relying on DNS not resolving the `.example` TLD. If a hostile DNS resolver returns an A record, the deny check could become a false negative on the first invocation; subsequent network filtering still applies. The script also skips the Docker-socket check when the host has no Docker socket, which is correct behavior but should be communicated in the test output.
- **No JSON-schema validation of the rendered settings file.** We trust our `RenderedPolicy` types match the SRT format. If SRT adds required fields or renames fields in a future major version, the rendered settings file will silently degrade. Mitigation: the smoke test runs `srt --settings <our-file> bash -c 'true'` indirectly via `claude-srt exec`; SRT will reject malformed settings and the smoke test will fail.
- **Spec mentions "the existing safehouse alias naming" without an inline definition.** The plan adopts the spec's fixed profile name `ios` and treats the safehouse alias as an external naming convention; the per-profile doc records the link verbally but does not introduce an external dependency. If the safehouse aliases change shape, only the doc text needs updating.
